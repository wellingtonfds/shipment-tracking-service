# ADR-001 — Adoção do Prisma ORM para Arquitetura Multi-tenant com NestJS e SQL Server

## Status
Aceito — 2026-09-16

## Contexto
O projeto NestJS exige uma arquitetura Multi-tenant isolada e escalável para atender múltiplos clientes no mesmo banco de dados Microsoft SQL Server (MSSQL). Enfrentamos o desafio de garantir o isolamento lógico rigoroso de dados por cliente (`tenant_id`), manter alta performance na execução de consultas, ter tipagem forte end-to-end e evitar o risco de vazamento de dados inter-tenants em tempo de execução. A solução precisava ser de fácil integração com os *Interceptors/Middlewares* nativos do NestJS para injeção automática de escopo.

## Decisão
Adotar o **Prisma ORM** utilizando *Prisma Client Extensions* e *Middlewares/Interceptors* do NestJS para implementar uma estratégia de isolamento Multi-tenant via coluna discriminadora (`tenant_id`) de forma transparente e automatizada em todas as operações com o SQL Server.

## Alternativas consideradas
- **TypeORM:** Recusado devido à complexidade de gerenciar *QueryRunners* customizados por requisição para isolamento de tenant de forma confiável e ao histórico de falhas na automação de *migrations* em esquemas complexos.
- **MikroORM:** Recusado devido à curva de aprendizado mais elevada exigida pelo padrão *Unit of Work* e gerenciamento manual de instâncias de contexto por tenant, impactando o prazo de entrega.
- **Múltiplos Schemas/Bancos por Tenant com Knex.js ou SQL Puro:** Recusado por gerar alto custo operacional de infraestrutura e manutenção no SQL Server, além de exigir controle manual de DTOs e mapeamento relacional.

## Consequências
**O que esta decisão facilita:**
- Isolamento transparente de dados por tenant via *Prisma Client Extensions* (injetando filtros globais automáticos nas queries sem poluir a camada de serviço).
- Alta produtividade do time com autocompletion, validação estática de schemas (`schema.prisma`) e *type-safety* nativo no TypeScript.
- Gerenciamento unificado e seguro das migrações do banco de dados SQL Server.
- Integração simplificada com *Request Scope* do NestJS para extração automática do ID do tenant via headers/JWT.

**O que esta decisão dificulta:**
- Exige atenção redobrada e testes automatizados estritos ao utilizar `$queryRaw` ou Stored Procedures no SQL Server, pois contornam os filtros de tenant automáticos do Prisma.
- Necessidade do passo de geração de código (`prisma generate`) no fluxo de CI/CD ao alterar o modelo de dados.
